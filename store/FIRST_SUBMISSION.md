# Chrome 웹 스토어 첫 등록

처음 한 번은 개발자 대시보드에서 새 항목을 만들고 ZIP을 올립니다. 이후의 버전 업데이트는 [배포 워크플로](../docs/RELEASE.md)로 처리할 수 있습니다. ZIP 업로드와 심사 제출은 서로 다른 단계입니다.

## 1. 제출 파일 준비

```sh
pnpm install --frozen-lockfile
pnpm run release:check
pnpm run test:release
pnpm run build
pnpm run release:package
```

- 제출 ZIP: `.output/release/`의 `unofficial-novelpia-patch-<버전>-chrome.zip` (빌드한 버전 사용)
- 무결성 확인: 같은 폴더의 `SHA256SUMS`
- 파일 목록·버전: 같은 폴더의 `release.json`

ZIP 루트에는 manifest.json이 있어야 합니다. `chrome-mv3-e2e` 빌드와 소스 코드 ZIP은 제출하지 않습니다. GitHub Release가 만들어진 뒤에는 해당 릴리스의 검증된 ZIP을 사용합니다.

## 2. 등록 초안 만들기

1. [개발자 대시보드](https://chrome.google.com/webstore/devconsole)에서 **새 항목**을 선택하고 ZIP을 업로드합니다.
2. 생성된 **32자 항목 ID**를 기록합니다. 게시자 ID와 항목 ID는 다릅니다.
3. [등록 자료](LISTING.md)의 이름·짧은 설명·상세 설명을 입력합니다.
4. `store/assets/01-reading.png`부터 `05-user-fonts.png`까지 스크린샷 5장, `promo-440x280.png` 작은 홍보 이미지와 `public/icons/icon128.png` 아이콘을 올립니다. [README에서 화면을 미리 확인](../README.md#화면-미리보기)할 수 있습니다.
5. 분류·기본 언어·개발자 연락처·배포 지역 등 대시보드의 필수 항목을 확인합니다.

이 단계에서는 초안을 저장할 수 있습니다. 계정 약관·데이터 공개 확인·연락처 등 소유자의 사실 확인이 필요한 항목은 실제 상태를 확인하고 작성하세요.

## 3. 개인정보와 공개 링크

[개인정보 안내](../docs/PRIVACY.md), 홈페이지, 지원 URL이 **로그아웃한 브라우저에서도 열리는지** 확인합니다. 비공개 GitHub 문서는 공개 개인정보 URL로 쓸 수 없습니다.

저장소 공개가 승인되지 않았다면 비공개를 유지하고 이 단계에서 멈춥니다. 별도의 공개 개인정보 페이지를 사용하는 경우에도 실제 동작과 일치해야 합니다. 데이터 처리 항목과 단일 목적·권한 설명은 [등록 자료](LISTING.md)를 기준으로 최종 대조합니다.

## 4. 자동 업데이트 연결

1. 개발자 대시보드의 계정 설정에 제출용 서비스 계정을 연결합니다. 기존 연결이 있으면 임의로 교체하지 않습니다.
2. GitHub의 `CWS_PUBLISHER_ID`, `CWS_EXTENSION_ID` 변수를 설정합니다.
3. [배포 운영](../docs/RELEASE.md)에 따라 무료 실행 조건·브랜치 보호를 확인합니다.
4. main의 CI에서 `store-status`를 수동 실행해 인증과 항목 조회를 확인합니다. 이 명령은 업로드·제출하지 않습니다.

Cloud 인증은 저장소의 제출 작업에만 필요합니다. 확장 사용자에게 Cloud 가입·결제·인증 키를 요구하지 않습니다.

## 5. 최종 심사 제출

- [ ] 실제 일반 빌드에서 핵심 기능과 서비스 경계를 확인했다.
- [ ] ZIP의 버전·해시와 검토한 릴리스가 일치한다.
- [ ] 스크린샷과 설명이 현재 기능을 정확히 보여준다.
- [ ] 개인정보 URL과 지원 링크가 비로그인 상태에서 열린다.
- [ ] 대시보드 필수 항목과 개인정보 공개 내용을 확인했다.
- [ ] 같은 항목에 다른 버전이 심사·공개 대기 중이지 않다.
- [ ] 최초 제출과 이후 자동 제출 활성화를 관리자가 승인했다.

최초 등록을 승인한 뒤 대시보드에서 심사를 요청하거나 자동 제출을 활성화해 승인된 main 릴리스를 제출합니다. 자동 제출은 심사를 건너뛰지 않으며 승인 후 공개를 요청합니다. 심사 기간과 Chrome의 업데이트 배포 시점은 별개입니다.

수동으로 이미 제출한 버전을 다시 올리지 않습니다. 스토어 상태를 먼저 확인하고, 다음 변경부터 버전을 올려 main으로 릴리스하세요.
